# Прошивка EDOG (Raspberry Pi)

Один сервис `edog` на Python:
- управляет 8 серво через PCA9685 (I²C);
- принимает Bluetooth-геймпад;
- отдаёт REST/WebSocket API.

На Pi работает только API. Веб-портал с 3D-моделью лежит в [`ui/`](../ui/) и запускается на ПК (см. «Портал» ниже).

```
edog/            код сервиса
  robot.py       контур 50 Гц: позы, наклоны, рысь, плавность, тесты серво
  kinematics.py  IK/FK ноги (бедро + голень)
  pca9685.py     драйвер PCA9685 и заглушка
  gamepad.py     геймпад (evdev)
  bluetooth.py   сопряжение через bluetoothctl
  api.py         REST + WebSocket
config/
  config.toml       железо, геометрия, раскладка геймпада (правится руками)
  calibration.json  калибровка серво (пишет портал)
os/
  setup.sh          настройка свежей Raspberry Pi OS
  pair-gamepad.sh   сопряжение геймпада по SSH
```

## Портал (на ПК)

```bash
python ui/serve.py            # http://localhost:8000/
python ui/serve.py --lan      # плюс доступ с телефона в той же сети
```

- **Адрес собаки** вводится в поле «Собака» в шапке, например `192.168.50.129:8080`, или передаётся ссылкой `?dog=…`. Браузер его запоминает.
- **Модели** портал берёт из [`cad/web/`](../cad/web/), их выгружает `cad/web/export_web_models.py` из FreeCAD. Если манифеста нет, собака рисуется примитивами.
- **Зависимостей нет**: нужен только Python, three.js лежит в `ui/vendor`, интернет не нужен.
- **Статусы в шапке** текстом: к какой собаке подключён портал, есть ли связь, PCA9685 и геймпад. При обрыве связи поверх модели появляется «НЕТ СВЯЗИ С СОБАКОЙ».

## Установка на Raspberry Pi

1. **Прошить SD-карту** в Raspberry Pi Imager: *Raspberry Pi OS Lite (64-bit)*. В настройках Imager задать:
   - hostname `edog`;
   - пользователя и пароль;
   - Wi-Fi;
   - включить SSH.
2. С ПК (Git Bash) отправить прошивку на Pi:
   ```bash
   firmware/os/deploy.sh <user>@edog.local
   ```
   На Pi попадает только `firmware/` (без тестов), меньше 1 МБ. Репозиторий, портал и CAD на Pi не нужны.
3. На Pi запустить настройку и перезагрузиться:
   ```bash
   ssh <user>@edog.local
   sudo ~/edog/firmware/os/setup.sh
   sudo reboot
   ```
   Скрипт включает I²C на 400 кГц и настраивает Bluetooth. Затем он ставит зависимости в `firmware/.venv` и регистрирует сервис `edog`, который стартует при загрузке.
4. На ПК запустить портал (`python ui/serve.py`) и указать адрес собаки. Документация API: **http://edog.local:8080/docs**

Проверки:
```bash
i2cdetect -y 1            # PCA9685 должен быть на 0x40
journalctl -u edog -f     # логи сервиса
sudo systemctl restart edog
```

Обновление кода — с ПК: `firmware/os/deploy.sh`. Скрипт заменит код, перезапустит сервис и не тронет venv и `calibration.json`.

## Проверка без PCA9685 и серво

Без платы сервис работает на заглушке: портал помечает драйвер как «нет PCA9685», остальное работает как обычно. Самодиагностика:

```bash
~/edog/firmware/os/check.sh
```

Скрипт проверяет ОС и питание RPi, I²C, группы пользователя, venv, сервис, API, 3D-модели, Bluetooth и геймпад. Отсутствие PCA9685 на 0x40 он помечает как WARN, а не ошибку.

## Сборка и калибровка (по одной ноге)

Все серво по умолчанию отмечены как **не подключённые**: сигнал на их каналы не идёт. Подключили ногу — отметили её серво в портале.

Для каждого серво (выбрать сустав на модели или строку в таблице):
1. **До установки крыла**:
   - отметить «подключено»;
   - включить «Серво»;
   - нажать **90° центр**;
   - надеть крыло так, чтобы сустав стоял в монтажном положении: бедро вертикально вниз, голень под 90° к бедру.
2. **Точная подстройка**: кнопками ±1° довести сустав точно до монтажного положения и нажать «Записать zero».
3. **Направление**: нажать «+5°». Бедро и голень должны повернуться вперёд, к голове. Если ушли назад, нажать «Инвертировать dir».
4. **Пределы**: осторожно подвести сустав к механическому упору и записать «min/max = текущий».
5. **Проверка**: «Проход по ходу» — серво медленно пройдёт min → max и вернётся.
6. **Сохранить калибровку**: она запишется в `config/calibration.json`.

Перёд собаки отмечен стрелкой на полу корпуса (`cad/custom/chassis_large.stl`) и зелёной стрелкой в портале. Каналы PCA9685: FL 0/1, FR 2/3, RL 4/5, RR 6/7 (бедро/колено), меняются в `config.toml`.

## Геймпад

**Сопряжение:**
1. Перевести геймпад в режим сопряжения.
2. В портале нажать «Найти устройства», затем «Сопрячь».

Без портала то же самое делает `firmware/os/pair-gamepad.sh`. Подходят геймпады со стандартной раскладкой Linux: DualShock 4, DualSense, Xbox (BT), 8BitDo.

| Управление | Действие |
|---|---|
| Левый стик | ходьба вперёд/назад, поворот (в режиме «Ходьба») |
| Правый стик | наклон корпуса (тангаж/крен) |
| Крестовина ↑/↓ | высота |
| A / ✕ | стойка |
| B / ○ | сидеть |
| X / □ | лечь |
| Y / △ | ходьба вкл/выкл |
| Start | серво вкл/выкл |
| Back / Share | аварийный стоп |

При потере связи собака останавливается и выравнивает корпус. Раскладка задаётся в `[gamepad]` в `config.toml`. Коды кнопок и осей конкретного геймпада можно посмотреть через `evtest`.

## API

Без авторизации, CORS открыт для любого адреса: рассчитано на домашнюю сеть. Документация Swagger — `/docs`.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/config` | геометрия, ноги, серво, позы, раскладка геймпада |
| GET | `/api/state` | полное состояние |
| POST | `/api/enable` `{enabled}` | подать/снять сигнал с серво |
| POST | `/api/estop` | аварийный стоп |
| POST | `/api/mode` `{mode}` | `stand` / `walk` / `manual` |
| POST | `/api/pose/{name}` | `stand`, `sit`, `lie`, `high` |
| POST | `/api/body` `{height, pitch, roll}` | положение корпуса |
| POST | `/api/drive` `{vx, turn}` | ходьба, −1…1; гаснет через 0.5 с без повтора |
| PUT | `/api/servos/{id}` `{angle}` или `{joint}` | угол серво или сустава (ручной режим) |
| POST | `/api/servos/{id}/test` `{action, delta}` | `center`, `ref`, `sweep`, `stop`, `nudge` |
| PATCH | `/api/servos/{id}/calibration` | `installed`, `zero`, `dir`, `min_deg`, `max_deg` |
| POST | `/api/servos/{id}/calibrate` `{joint}` | «сустав сейчас = joint°» → zero |
| POST | `/api/calibration/save` | записать calibration.json |
| PATCH | `/api/power` `{limit_a, servo_a}` | лимит тока серво: подключить можно не больше `limit_a / servo_a` приводов; сохраняется сразу |
| GET | `/api/bluetooth/scan` | поиск устройств |
| POST | `/api/bluetooth/pair` / `remove` `{mac}` | сопряжение / забыть |
| WS | `/ws` | состояние 20 раз/с; клиент шлёт `{"type":"drive"}` / `{"type":"servo"}` |

Id серво: `FL_hip`, `FL_knee`, `FR_hip`, … Углы суставов:
- **hip**: 0° — бедро вниз, + — лапа вперёд;
- **knee**: 0° — голень на линии бедра, + — голень вперёд.

## Разработка на ПК

```bash
cd firmware
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt pytest   # Linux: .venv/bin/pip
.venv/Scripts/python -m edog --mock                     # API на http://localhost:8080/
python ../ui/serve.py                                   # портал: http://localhost:8000/?dog=localhost:8080
.venv/Scripts/python -m pytest
```
