# XIAO ESP32-S3 Sense

Всё, что относится к плате Seeed XIAO ESP32-S3 Sense, которая заменяет Raspberry Pi. Код для RPi лежит в `rpi/`.

```
firmware/edog/       — прошивка собаки: серво, BLE-геймпад, API для портала, видео с камеры, патруль по камере
firmware/xiao_test/  — тестовая прошивка: API состояния, видео камеры, звук микрофона, настройка Wi-Fi
ui/                  — страница проверки для xiao_test, запускается на ПК (на плате только API)
start.cmd            — запуск страницы проверки: http://localhost:8001/
ota.py               — сборка и прошивка собаки по воздуху (сборка кладётся в build/, не в git)
models/              — модель людей ESP-DL (.espdl) и скрипт, который делает из неё pedestrian_model.h
backup/              — сохранённые прошивки для отката
```

## Прошивка собаки (`firmware/edog`)

Перенос сервиса с Raspberry Pi: та же логика (позы, рысь, движения, демо, калибровка, лимит тока, защита колена от рамы) и тот же API. Общий портал [`ui/`](../ui/) работает с ней без изменений и дополнительно показывает видео с камеры.

| Файл | Что | Аналог на Pi |
|---|---|---|
| `config.h` | железо, геометрия, профили шага, раскладка геймпада | `config/config.toml` |
| `robot.cpp` | контур 100 Гц, позы, рысь, демо, калибровка | `robot.py`, `demo.py`, `power.py` |
| `kinematics.h`, `leg_hull.h` | IK ноги, защита колена от рамы | `kinematics.py`, `collision.py`, `leg_hull.json` |
| `pca9685.cpp` | драйвер PCA9685, без платы — заглушка | `pca9685.py` |
| `gamepad.cpp`, `hid.cpp` | BLE-геймпад и его сопряжение | `gamepad.py`, `bluetooth.py` |
| `api.cpp` | REST + WebSocket | `api.py` |
| `camera.cpp` | захват кадров, видео MJPEG с заголовками зрения | — |
| `vision.cpp`, `pedestrian.cpp` | зрение: люди (ESP-DL), пол, закрытость, кадры в фазе шага | — |
| `patrol.cpp` | патруль: автомат, карта вокруг, память мест ([docs/patrol.md](../docs/patrol.md)) | — |

### Сборка и прошивка

Нужен [arduino-cli](https://arduino.github.io/arduino-cli/) с ядром ESP32 (`esp32:esp32`, ставится из `https://espressif.github.io/arduino-esp32/package_esp32_index.json`) и две библиотеки:

```
arduino-cli lib install ArduinoJson NimBLE-Arduino
arduino-cli compile -b esp32:esp32:XIAO_ESP32S3:PSRAM=opi xiao/firmware/edog
arduino-cli upload  -b esp32:esp32:XIAO_ESP32S3:PSRAM=opi -p COM3 xiao/firmware/edog
```

- Без `PSRAM=opi` камера не запустится.
- По USB прошивать нужно только первый раз. Дальше — по воздуху, см. ниже.
- Папка библиотек должна лежать по пути без кириллицы, иначе компилятор не найдёт заголовки. По умолчанию это `Документы\Arduino`; перенести можно так: `arduino-cli config set directories.user C:\Users\<имя>\Arduino`, после этого библиотеки поставить заново.

### Прошивка по воздуху

Скрипт собирает прошивку, проверяет собаку, заливает её через API и ждёт, пока плата перезагрузится с новой:

```
python xiao/ota.py                                  # собрать и залить на edog.local:8080
python xiao/ota.py --dog 192.168.50.130:8080        # по IP, если .local не находится
python xiao/ota.py --bin xiao/build/edog.ino.bin    # залить готовый файл без сборки
python xiao/ota.py --build-only                     # только собрать в xiao/build/
```

Код выхода 0 — новая прошивка работает, 1 — нет, причина в выводе. Скрипт подходит и для агентов: он не интерактивный.

То же из портала: блок «Прошивка платы» → «Обновить прошивку…» → файл `xiao/build/edog.ino.bin`. Портал сам перезагрузится, когда плата вернётся с новой прошивкой.

- **Включённые серво выключаются сами:** на перезагрузке контур не держит ноги, поэтому собака сначала встаёт в монтажное положение и снимает сигнал (как при деплое на Pi). Пока идёт запись, серво не включаются ни из портала, ни с геймпада.
- **Обрыв не страшен.** Прошивка пишется во второй слот флеша. Плата переключается на неё, только если файл дошёл целиком и образ цел, иначе остаётся на старой.
- **Нужен `edog.ino.bin`.** `bootloader.bin`, `merged.bin` и `partitions.bin` плата и скрипт отклоняют.
- **Какая прошивка стоит:** `GET /` и `/api/config` отдают `firmware` — начало SHA-256 работающей прошивки.
- **Без пароля, как и всё API:** обновить прошивку может любой в домашней сети.
- **Откат.** Новая прошивка сначала «на проверке». Рабочей она становится, когда API поднялось и проработало 20 с. Если за 90 с этого не случилось (зависла, падает по кругу), плата перезагружается, и загрузчик возвращает прежнюю. Проверено на собаке. Прошивку, залитую по USB, откатывать некуда.

### Подключение

```text
XIAO D4 (GPIO5) ── SDA PCA9685
XIAO D5 (GPIO6) ── SCL PCA9685
XIAO 3V3        ── VCC PCA9685 (логика)
XIAO GND        ── GND PCA9685, общий с питанием серво
```

Каналы серво (бедро/колено): FL 4/5, RL 6/7, FR 8/9, RR 10/11 — не те, что были на Pi. Пины, адрес PCA9685 и каналы меняются в `config.h`. Если PCA9685 не отвечает, прошивка работает на заглушке, и портал пишет «НЕТ PCA9685».

### Wi-Fi и портал

Сеть задаётся так же, как в тестовой прошивке: командой в Serial (115200) `wifi <ssid> <пароль>`, ещё есть `forget` и `status`. Если сеть не задана или к ней не подключиться за 15 с, плата поднимает точку доступа `EDOG-XIAO` (пароль `edog1234`, адрес `192.168.4.1`).

В сети плата доступна как `edog.local`, API на порту 8080, как у Pi. Поэтому портал на ПК (`start.cmd` в корне) находит её по адресу по умолчанию `edog.local:8080`. Адрес можно задать и вручную, например `?dog=192.168.50.130:8080`. Команда `status` печатает готовую ссылку.

### Патруль

После включения питания собака сама встаёт, через 5 с кивает и патрулирует: ищет новые места и людей, встретив человека — приветствует. Как это устроено, как калибровать и как читать радар — [docs/patrol.md](../docs/patrol.md).

Памяти на плате впритык. Модель людей (0,43 МБ) встроена в прошивку массивом (`pedestrian_model.h`, делается `python xiao/models/espdl_to_header.py`). ESP-DL взят из ядра Arduino, но без его предобработки изображений: она тянет ~650 КБ кода и не влезает в слот. Внутренней RAM после старта остаётся около 40 КБ, поэтому стеки задач зрения и патруля, буферы кадров и обычные `malloc` от 512 байт (`EXTMEM_LIMIT`) лежат в PSRAM.

### Видео

Камера отдаёт MJPEG на `http://edog.local:8081/stream`: VGA 640×480, 8 кадров в секунду. Частота, разрешение, качество JPEG и переворот кадра задаются в `config.h` (`CAMERA_*`). В портале блок «Камера» появляется, только если плата сообщила о камере. Видео можно выключить галочкой, тогда оно не занимает Wi-Fi.

Поток один на всех. Если видео уже смотрит другое устройство (другая вкладка портала, [приложение на телефоне](../android/)), портал и приложение спрашивают, переключить ли видео сюда. Если да, видео уходит на новое устройство, а у прежнего появляется тот же вопрос — «вернуть сюда?». Когда зритель отключается, поток свободен, и его подхватывает тот, кто ждёт.

### Геймпад

BLE-геймпад (Xbox Wireless Controller, 8BitDo в BLE-режиме и другие HID-геймпады) сопрягается из портала: «Найти устройства», затем «сопрячь». Сопряжение хранится на плате. После перезагрузки собаки или геймпада подключение восстанавливается само: достаточно включить геймпад.

Раскладка в `config.h` задаётся кодами Linux, как в `config.toml` на Pi (`BTN_A`, `ABS_RZ` и т. д.). Прошивка переводит HID-отчёт геймпада в эти коды так же, как это делает ядро Linux, поэтому раскладка Xbox переносится как есть. Последнюю нажатую кнопку портал показывает в блоке «Геймпад».

### Калибровка

Кнопка «Сохранить» в портале пишет калибровку серво, лимит тока, профиль шага и поправку наклона в NVS платы. Это аналог `calibration.json` на Pi. Перепрошивка её не стирает, полная очистка флеша (`erase_flash`) стирает.

Калибровку с Pi можно загрузить файлом. Копия с собаки лежит в `rpi/firmware/config/calibration.json`, забрать свежую с Pi: `scp edog:edog/firmware/config/calibration.json rpi/firmware/config/`.
1. Выключить серво.
2. В портале нажать «Загрузить из файла» и выбрать `calibration.json`.
3. Нажать «Сохранить».

Файл сначала проверяется целиком: при ошибке ничего не меняется. Чего в файле нет (например, `scale` у старой калибровки), остаётся как было.

### API

То же, что на Pi (см. [rpi/firmware/README.md](../rpi/firmware/README.md#api)), плюс:

- в `/api/config` есть `camera` (`ok`, `sensor`, `port`, `path`, `fps`);
- в состоянии есть `camera` (`fps`, `clients`, `viewer` — id зрителя видео, 0 — поток свободен);
- `GET :8081/stream?id=<id>` — видео; `id` — число, которым зритель себя называет. 409 — поток только что забрало другое устройство;
- `POST /api/camera/take` (`{"id": <id>}`) — забрать видео себе: прежний зритель отключается, следующие 5 с поток ждёт этот `id`;
- `GET /` и `/api/config` отдают `firmware`, состояние — `updating`;
- `POST /api/firmware` — тело — файл `edog.ino.bin`; включённые серво сначала выключаются (монтажное положение); после записи плата перезагружается;
- `PUT /api/calibration` — калибровка целиком в формате `calibration.json`, только при выключенных серво; в NVS — `/api/calibration/save`.
- патруль и зрение — `/api/patrol`, `/api/vision/…`, в состоянии `patrol` и `vision`; заголовки кадров видео `X-Detect`, `X-Free`, `X-Vision`, `X-Patrol`, `X-Map` — см. [docs/patrol.md](../docs/patrol.md#api);
- движения `nod` (кивок), `wag` (виляние), `bow` (поклон) — к `jump` и `joy`; крестовина → на геймпаде — патруль вкл/выкл.

Swagger `/docs` на плате нет.

## Тестовая прошивка (`firmware/xiao_test`)

Проверка камеры, микрофона и SD без собаки:

```
arduino-cli compile -b esp32:esp32:XIAO_ESP32S3:PSRAM=opi xiao/firmware/xiao_test
arduino-cli upload  -b esp32:esp32:XIAO_ESP32S3:PSRAM=opi -p COM3 xiao/firmware/xiao_test
```

Wi-Fi задаётся так же, как у прошивки собаки, имя в сети — `edog-xiao.local`.

| Порт | Путь | Что |
|---|---|---|
| 80 | `GET /api/status` | состояние: Wi-Fi, камера, микрофон, SD, PSRAM, температура |
| 80 | `GET /api/control?framesize=&vflip=&hmirror=` | настройки камеры |
| 80 | `GET /api/scan` | список сетей Wi-Fi |
| 80 | `POST /api/wifi` (`ssid`, `pass`) | сохранить сеть и перезагрузиться |
| 81 | `/stream` | видео MJPEG |
| 82 | `/audio` | сырой PCM 16 кГц, 16 бит, моно |
