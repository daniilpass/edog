# Raspberry Pi собаки EDOG

## Подключение

Хост — Raspberry Pi 3B+, Raspberry Pi OS Lite 64-bit (Trixie), пользователь `edog`.

```bash
ssh edog '<команда>'
```

Алиас `edog` задан в `~/.ssh/config` на ПК разработчика:
- адрес 192.168.50.129;
- пользователь `edog`;
- ключ `~/.ssh/edog_ed25519` без парольной фразы.

Вход по паролю тоже включён. Пароль в репозиторий не записываем.

- **Всегда `ssh edog`, а не `edog.local`.** Git Bash на этом ПК не разрешает mDNS-имена.
- **Не открывай интерактивную сессию.** Только `ssh edog '<команда>'`, по одной задаче за вызов. Ответить на запрос пароля или на `[Y/n]` ты не можешь. Для apt добавляй `-y`, для sudo используй `sudo -n`.
- **sudo без пароля** включён правилом `/etc/sudoers.d/010_edog-nopasswd`. Если `sudo -n` отвечает «a password is required», например после переустановки ОС, попроси пользователя создать это правило заново. Пароль в чате не проси.
- **Если не подключается:**
  1. `ping -n 1 192.168.50.129` из PowerShell и `Test-NetConnection 192.168.50.129 -Port 22`.
  2. IP мог смениться (DHCP). Попроси пользователя посмотреть адрес Pi в роутере, поправь `HostName` в `~/.ssh/config` и посоветуй закрепить адрес за Pi в роутере.
- **Если ключ не принимается** (`Permission denied (publickey,password)` при `-o BatchMode=yes`), например после переустановки ОС:
  - пароль у пользователя не спрашивай и в чат его не проси;
  - попроси пользователя один раз выполнить в PowerShell:
    ```powershell
    type $HOME\.ssh\edog_ed25519.pub | ssh edog@192.168.50.129 "umask 077; mkdir -p ~/.ssh; cat >> ~/.ssh/authorized_keys"
    ```
  - после переустановки ОС поменяется ключ хоста. Убери старую запись: `ssh-keygen -R 192.168.50.129`.

## Частые задачи

**Сервис и логи:**
```bash
ssh edog 'systemctl status edog --no-pager -n 0; journalctl -u edog -n 50 --no-pager'
ssh edog 'sudo -n systemctl restart edog'
```

**Самодиагностика** (ОС, питание, I²C, права, venv, сервис, API, Bluetooth, геймпад):
```bash
ssh edog '~/edog/firmware/os/check.sh'
```
Если PCA9685 ещё не подключена, предупреждение об этом в выводе нормально.

**Обновить код.** На Pi лежит только то, что нужно для работы:
- `~/edog/firmware/` без тестов, с venv в `firmware/.venv`;

Git-репозитория и исходников CAD на Pi нет, и так и должно оставаться: место на SD ограничено. Деплой делается с ПК:
```bash
/c/git/edog/firmware/os/deploy.sh
```
Скрипт берёт текущие файлы рабочей копии (включая незакоммиченные) и отправляет их по SSH одним архивом меньше 1 МБ. На Pi он целиком заменяет `firmware/edog`, затем перезапускает сервис и проверяет, что тот поднялся.

На Pi работает только API. Портал (`ui/`) и модели (`cad/web/`) на Pi не возить.

На Pi скрипт не трогает:
- `.venv`;
- `firmware/config/calibration.json`: калибровка серво живёт только на Pi. Если её нужно сохранить в репозиторий, забери её через `scp edog:edog/firmware/config/calibration.json /c/git/edog/firmware/config/`.

Если менялся `requirements.txt` или `setup.sh`, после деплоя запусти:
```bash
ssh edog 'sudo -n env DEBIAN_FRONTEND=noninteractive ~/edog/firmware/os/setup.sh'
```

**API:** http://192.168.50.129:8080/ (Swagger: `/docs`).

**Портал** запускается на ПК: `python ui/serve.py`, затем открыть http://localhost:8000/?dog=192.168.50.129:8080.

## Питание

```bash
ssh edog 'vcgencmd get_throttled; vcgencmd measure_clock arm; vcgencmd measure_temp; journalctl -k -b --no-pager | grep -c "Undervoltage detected"'
```

Расшифровка `get_throttled`:

| Бит | Маска | Значение |
|---|---|---|
| 0 | 0x1 | напряжение ниже нормы сейчас (< ~4.63 В) |
| 1 | 0x2 | частота ограничена сейчас |
| 2 | 0x4 | троттлинг сейчас |
| 3 | 0x8 | мягкий температурный предел сейчас |
| 16–19 | 0x10000…0x80000 | то же, но «было с момента загрузки» |

`0x0` — всё в порядке. `0x50000` — просадки были, сейчас их нет. `0x50005` — просадка прямо сейчас, и процессор сброшен до 600 МГц.

Сравнивать варианты питания надо **после перезагрузки** (`sudo -n reboot`), потому что биты «было» сбрасываются только ей. Затем:
1. 2–3 минуты простоя;
2. 60 секунд нагрузки на все 4 ядра: `for i in 1 2 3 4; do timeout 60 sh -c 'while :; do :; done' & done; wait`;
3. всё это время каждые 2 с опрашивать `get_throttled`.

Нагрузочный тест не запускай, если просадка есть уже в простое: просадки под нагрузкой портят SD-карту.

Журнал замеров по вариантам питания — в `docs/hardware.md`, раздел «Питание RPi: замеры».
